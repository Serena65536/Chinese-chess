## 1. 产品范围

### 1.1 v1.0 必须做到

1. **本地双人**：同一台电脑轮流走棋（也是规则引擎的调试台）。
2. **远程联机**：开房 → 出 6 位房间码 → 对方输码入局 → 双方就绪开局。
3. **完整对局流程**：将军提示、将死、困毙、三次重复判和、60 回合自然限着判和、长将判负、认输、求和、超时判负、掉线判负。
4. **计时**：30 分钟保留时间 + 每步 30 秒读秒（详见 5.4）。
5. **断线重连**：90 秒宽容期内恢复，局面不丢。
6. **个性化三件套**：背景图、头像、背景音乐；设置持久化。
7. **Windows 安装包**：双击可装，含客户端与服务端两件套。

### 1.2 v1.0 明确不做

- 人机对战（AI 引擎）
- 注册账号 / 好友列表 / 战绩排行
- 对局内聊天、观战、悔棋
- 长捉 / 长打 / 一将一杀的自动判罚（只提示）
- 手机端、网页端
- 自动更新、加秒计时、房主自定义时间（都留 v1.1）

### 1.3 后续版本

v1.1：自动更新、棋谱复盘与导出、中式记谱（炮二平五）、棋盘/棋子皮肤、观战、开房自定义时间。
v1.2：账号与好友、排位、残局编辑器。

## 2. 已确认的决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 先只做 Windows，代码保持跨平台 | 打包与测试成本最低；Qt 同一套代码以后可出 mac/Linux |
| D2 | **Python + PySide6（Qt6）**，不用 Electron/Tauri/Godot/.NET | 你会 Python，客户端/服务端/引擎同一门语言，零学习成本；本机 PySide6 6.11 + PyInstaller 已就位。原 Electron 判断的前提（"都不太熟"）不成立，已推翻 |
| D3 | 中心服务器 + 6 位房间码，服务端权威；服务器**可自建** | 家用宽带多在 NAT 后，只有服务端方案保证任意网络可连；顺带解决掉线、防改棋、计时仲裁 |
| D4 | 头像同步给对手；背景图与 BGM 各自本地 | 头像 ~20KB 成本可忽略；背景/BGM 体积大且涉及版权 |
| D5 | 规则「实用完整版」，长捉只提示 | 覆盖 99% 实战、可解释不误判；完整长捉判定要 +2~3 周 |
| D6 | 附加功能只做「求和/认输」+「计时」 | 控制范围；聊天、观战、悔棋留 v1.1 |
| **D7** | **程序名「一起来下棋」** | 用户指定；配置目录、安装包、窗口标题统一用它 |
| **D8** | **计时：30 分钟保留 + 每步 30 秒读秒，超时判负** | 用户指定；真读秒（byo-yomi），非加秒 |
| **D9** | **视觉：传统木纹 + 立体棋子** | 用户指定；与"一起来下棋"的居家气质一致，且和用户自选背景图不打架 |

## 3. 技术选型

### 3.1 方案对比

| | **A. Python + PySide6（选定）** | B. Electron + React | C. Tauri 2 | D. Godot 4 |
|---|---|---|---|---|
| 要学的语言 | **没有** | TypeScript | TS + Rust | GDScript/C# |
| 棋盘渲染 | QGraphicsView 自带缩放/命中/动画 | Canvas 手写 | 同 B | 引擎自带 |
| 音频 | QtMultimedia（mp3 开箱） | HTML5 Audio + WebAudio | 同 B | 引擎音频总线 |
| 安装包 | 60–150MB | 150–250MB | 10–20MB | 50–100MB |
| 启动 | 1–2 秒 | 2–4 秒 | <1 秒 | <1 秒 |
| 界面美观度 | 默认朴素，需写 QSS | 最好 | 同 B | 中 |
| 服务端同语言 | **是** | 是（Node） | 否 | 否 |
| 主要风险 | 打包体积/杀软误报/界面美化 | 包体大、学 TS | Rust 工具链 | 设置页手搓 |

**结论：A。** 两条硬理由：①你会 Python，三端一门语言、引擎一份代码共用；②`QGraphicsView` 天生处理缩放、命中检测和补间动画，象棋这种场景比手写 Canvas 省事一个数量级。代价已写进 R2/R6。

### 3.2 技术清单

| 层 | 选择 | 说明 |
|---|---|---|
| 界面 | PySide6 6.11（Qt 6，LGPL） | 官方绑定，动态链接可闭源分发 |
| 棋盘 | `QGraphicsView` + `QGraphicsScene` | 棋子是 item，动画用 `QPropertyAnimation` |
| 音频 | `QMediaPlayer`（BGM）+ `QSoundEffect`（音效） | 两套独立音量；BGM 淡入自己写补间 |
| 棋规内核 | `xiangqi_core` 纯 Python 包（800–1200 行） | 零 Qt 依赖，客户端与服务端 import 同一份 |
| 客户端联机 | `QtWebSockets`（`QWebSocket`） | 跑在 Qt 事件循环，不混用 asyncio |
| 服务端 | Python + `aiohttp` | 一个依赖同时给 HTTP（头像）和 WebSocket |
| 数据 | 标准库 `sqlite3` | 仅服务端用；客户端配置写 JSON |
| 配置/校验 | dataclass + 手写校验 | 不引入 pydantic |
| 测试 | `pytest` | 局面库驱动 + 双客户端对局脚本 |
| 打包 | PyInstaller（onedir）+ NSIS | 排除 QtWebEngine/Qt3D，目标 60–90MB |

Python 3.11.9 ✅ ｜ PySide6 6.11.0（含 QtMultimedia / QtWebSockets / QtSvg / QtNetwork）✅ ｜ PyInstaller ✅ ｜ aiohttp、pytest ❌（开工第一条命令补）

## 5. 核心设计

### 5.1 棋规引擎（最大工作量、最需要测试）

**数据结构**：9×10 棋盘，内部一维列表 + 棋子枚举；对外用标准中国象棋 FEN 交换状态（`rheakaehr/9/.../RHEAKAEHR w - - 0 1`），重连时下发 FEN + 着法历史。

**必须实现**

- 七类棋子走法（含马腿、象眼、炮架、九宫限制、兵过河）
- 自杀检测：导致己方被将军的着法非法
- 终局：无合法着法时，被将军＝将死；否则＝困毙（困毙也判负）
- 重复局面：同一局面（含走子方）出现三次 → 长将方负，否则判和
- 自然限着：60 回合无吃子 → 判和
- 长将检测：连续将军且局面循环 → 长将方负
- 长捉：**只检测 + 提示**，弹窗建议协商，不自动判罚

**测试**：局面库驱动，每条规则配 3–5 个 FEN 快照；引擎单测 ≥80 用例。改为 Python 后跑测试就是 `pytest`，秒级反馈。

### 5.2 棋盘与交互（视觉：传统木纹 + 立体棋子）

- **木纹**：程序生成（条纹 + 噪声 + 轻微色差），不是下载的图片；外框深木色描边，九宫斜线、河界"楚河汉界"用 QPainter 绘制。
- **棋子**：径向渐变模拟弧面高光 + 底部椭圆投影 + 边缘描边，红黑双色；文字优先楷体（KaiTi），启动时用 `QFontDatabase` 探测，缺则回退微软雅黑/系统默认。
- **可重生成**：所有图形参数集中在 `artwork.py`，改一行重跑即可出新版，不用重画。
- **交互**：点击选中 → 高亮合法落点 → 点击落点；拖拽留 v1.1。
- **动画**：走子补间 150–200ms、吃子淡出、最后一步起止标记、将军红闪。
- **视角**：执黑自动翻转棋盘。
- **背景与棋盘的层级**：用户背景图铺在**棋盘外围**，棋盘本身保持不透明木质——避免透明棋盘导致棋子对比度不足。设置里提供"背景暗化"与"棋盘阴影"两个滑块。

### 5.3 联机协议

WebSocket + JSON，服务端每条消息带递增 `seq`，客户端重连后按 `seq` 补差。

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `hello{name,avatarId,ver}` | 握手 + 客户端版本 |
| C→S | `create_room{}` | 回 6 位房间码 |
| C→S | `join_room{code}` | 校验存在性/人数/密码 |
| C→S | `ready{}` | 双方 ready 自动开局 |
| C→S | `move{from,to,seq}` | 服务端校验合法性、轮次、是否超时 |
| C→S | `resign` / `offer_draw` / `accept_draw` | 认输、求和 |
| C→S | `reconnect{roomToken}` | 断线重连，凭 token 恢复身份 |
| C→S | `ping{t}` | 心跳 15 秒 |
| S→C | `room_state{players,status}` | 房间快照（人数/头像/准备态） |
| S→C | `game_start{fen,red,black,clock}` | 开局 + 计时配置 |
| S→C | `move_applied{seq,move,fen,clock}` | 走子广播（权威 FEN + 剩余时间相位） |
| S→C | `illegal{reason}` | 非法着法说明 |
| S→C | `game_over{winner,reason}` | 将死/困毙/认输/求和/超时/长将/掉线 |
| S→C | `opponent_offline{graceMs}` | 对手掉线，进入宽容期 |

- **同步原则**：回合制不做客户端预测，一律「服务端判 → 广播 → 渲染」，天然无回滚。
- **房间状态机**：`EMPTY → WAITING → READY → PLAYING → FINISHED → (再来一局 | CLOSED)`，30 分钟无人回收。
- **服务端三重校验**：轮到谁 + 着法合法 + 未超时。

### 5.4 计时与读秒（D8 落地口径）

**规则**

- 双方各 **30 分钟**保留时间（1 800 000 ms）
- 保留时间用尽后进入**读秒**：每一步必须在 **30 秒**内落子，超时立即判负
- 读秒阶段每走完一步，读秒重新计满 30 秒（单次读秒，不累积）
- 保留时间阶段的走子只扣实际思考时间；读秒阶段不扣保留时间（已为 0），也不影响下一步的 30 秒
- 不做加秒、不做罚时、v1.0 不支持房主改时间（固定 30+30）

**权威与显示**

- 服务端持有双方剩余时间，用 `time.monotonic()` 计时，不受系统时间调整影响；只在轮到该方时走表
- 客户端做**显示层平滑**（本地每 100ms 插值），每 250ms 与服务端权威值校正，避免网络抖动让数字乱跳
- 每次 `move_applied` 带 `{redMs, blackMs, phase, byoyomiMs}`

**断线与时钟（关键取舍）**

- 一方掉线 → **双方时钟全部暂停**，进入 90 秒宽容期，界面提示"对手断线，剩余 90 秒"
- 宽容期内回到房间 → 恢复计时，局面原样
- 超时未回 → 判掉线方负（`reason: "disconnect"`）
- 选择"暂停"而非"继续扣时"的理由：象棋是回合制，暂停不产生不公平；且 90 秒封顶，恶意断网也占不到便宜

**界面**

- 双方时间条，轮到谁谁高亮
- 保留时间 < 1 分钟变黄；进入读秒显示"读秒 30"且最后 10 秒数字闪动 + 可选滴答音效（可关）
- 超时瞬间定格并弹出结果，避免"到底谁超时"的争议

### 5.5 个性化素材

**背景图**：选择本地 `png/jpg/webp` → 复制进 `%APPDATA%/一起来下棋/media/backgrounds/`（不引用原路径，防用户删文件后白屏）；显示模式填充/适应/拉伸；暗化蒙版 + 模糊可调；支持多图列表与轮换。

**头像**：本地选图 → 圆形裁剪 → 压成 256×256 WebP（~20KB）→ 上传服务端 → 对手在房间内可见；服务端做 MIME 校验、≤256KB、重编码、哈希文件名（防路径穿越）；未上传则按昵称首字生成色块头像。

**背景音乐**：本地 mp3/ogg/wav；播放列表、顺序/单曲/随机、音量、开局淡入 2 秒、终局切歌；BGM 与音效两套独立音量；`errorOccurred` 捕获后提示"这个文件放不了"并跳过。

### 5.6 设置与持久化

- 客户端：`%APPDATA%/一起来下棋/config.json`，dataclass 定义 + `schemaVersion` 迁移
- 服务端：SQLite 三表 `games` / `rooms` / `avatars`
- 卸载不删用户素材目录
